# Software Engineering Principles & Architectural Decisions

## Core Principles

### DRY (Don't Repeat Yourself)

- Every piece of knowledge should have a single, unambiguous, authoritative representation within the system
- Avoid duplicating logic across layers or modules
- Extract common functionality into reusable components
- If you find yourself copying code, refactor into a shared utility or base class

### Modularity

- Keep components loosely coupled and highly cohesive
- Each module should have a clear, single responsibility
- Dependencies should flow in one direction: UI → Analysis → Domain
- Changes in one module should not require changes in unrelated modules
- Favor composition over inheritance where appropriate
